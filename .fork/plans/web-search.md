# Web search — план отчуждения

Три провайдера поиска: Brave, DuckDuckGo, Tavily.

## Состояние

В приложении не проверялось, тесты зелёные (проверено 2026-10-04 вместе с остальными клиентскими пакетами). Три новых пакета: `packages/web/web-search-brave`, `web-search-duckduckgo`, `web-search-tavily`.

В рабочем профиле выбран `tavily` (`searchProvider: tavily`), то есть на практике используется он. Шесть из восемнадцати линт-ошибок репозитория приходятся на эти пакеты, ещё семь — на апстримную карточку настроек, которую они правят; разбор в [../STATUS.md](../STATUS.md#общее).

## Чем связан с ядром

Это самый дешёвый случай из трёх плагинов — апстримные правки почти целиком косметические.

| Апстримный файл | Что добавлено | Обязательно? |
|---|---|---|
| `packages/web/web/src/index.ts` | `WEB_SEARCH_PROVIDER_IDS`, `WEB_FETCH_PROVIDER_IDS` и типы вокруг них | **нет** |
| `packages/client/ui-settings-web-search/*` (7 файлов) | рендер новых провайдеров в карточке настроек | нет, но без этого их не выбрать мышью |
| `packages/web/web-fetch-http/*` (4 файла) | правки fetch-провайдера | разобраться отдельно |

### Почему список id не обязателен

JSDoc самого `WEB_SEARCH_PROVIDER_IDS` отвечает на это прямо: список — это *известные* id, а не *принимаемые*. `WebRuntime` регистрирует id любого плагина, и конфигурация, назвавшая отсутствующий в списке id, обязана загрузиться и упасть на выборе с `WEB_PROVIDER_CONFIGURED_MISSING`, а не быть отвергнутой схемой.

То есть **регистрация провайдера уже работает без правок ядра**. Список нужен ровно для одного: чтобы страница настроек показала провайдера в выпадашке. Это выбор между «правка ядра» и «провайдер настраивается из `cordis.patch.yml`, а не мышью».

## Шаги

- [ ] Проверить, что все три провайдера работают — сейчас готовность неизвестна
- [ ] Починить шесть линт-ошибок в своих пакетах (остальные семь — в апстримной карточке, уедут вместе с решением по ней)
- [ ] Выяснить, что именно правится в `web-fetch-http` и обязательно ли это
- [ ] Снять правку `WEB_SEARCH_PROVIDER_IDS`, убедиться что провайдеры по-прежнему регистрируются и выбираются через конфиг
- [ ] Решить судьбу карточки настроек: либо своя карточка в своём пакете, либо отказ от выбора мышью
- [ ] Заменить `workspace:*` на semver-рэнджи
- [ ] Проверить установку на чистый профиль

## Замечание

Если снятие правки `WEB_SEARCH_PROVIDER_IDS` подтвердится, web-search переходит из «почти» в «чисто» — три пакета без единой апстримной правки. Это первый кандидат на отчуждение: дешевле всех и даёт проверенный на практике шаблон для остальных — именно поэтому установка на чистый профиль начинается с него (приоритет 10 в [../STATUS.md](../STATUS.md#приоритеты)).
