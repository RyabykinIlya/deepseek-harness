# Model review — механизм пересмотра тиров

Скрипт: [`model-review.py`](model-review.py). Запускать, когда вендоры
пере shuffled модели/цены — новый релиз, repricing, вывод модели — или по
выбранному кадансу; снимки датированы, так что дрейф виден между любыми
двумя запусками.

```sh
python3 .fork/tools/model-review.py                  # полный обзор (сеть)
python3 .fork/tools/model-review.py --offline        # пересчёт latest.json без сети
python3 .fork/tools/model-review.py --baseline FILE  # дрейф против конкретного снимка
```

Выход: `.fork/reports/model-review/<дата>.json` (снимок — история и базлайн
следующего прогона), `latest.json`, `report.md`. Exit-коды: 0 — чисто,
1 — есть перестановки или устаревшие Go-маппинги (требуют решений),
2 — жёсткая ошибка (сеть/конфиг). Advisory-разделы (дрейф, кандидаты,
дубликаты) не влияют на exit.

## Что он проверяет

| Проверка | Вопрос |
|---|---|
| Перестановки | модель в тире, качеству которого её score уже не соответствует |
| arena.ai Code Arena | Elo/место каждой тир-модели на человеческой арене — третье мнение рядом с AA и Design Arena |
| Устаревшие Go-маппинги | `modelMap` указывает на модель, которой больше нет в подписке Go — начнёт 404 на диспатче |
| Ёмкость Go не используется | модель есть в подписке, но ни один тир её не замапил |
| Дубликаты | одна модель в двух тирах (осознанно?) |
| Не измерено | тир-модель с low coverage метрик — её нельзя судить, нужны данные |
| Пропало из каталога | id резолвится в ничто (`stealth/space-bunny-alpha` так и был найдены) |
| Кандидаты | модели ≥ pro-порога, которых нет ни в одном тире |
| Дрейф | против прошлого снимка: \|Δscore\| ≥ 2 или цена ±20% |

## Правило размещения (детерминированное)

Composite score — те же веса, что [`openrouter-rank.py`](MODEL-RANKING.md)
(coding .40 / agentic .20 / intel .15 / arena_code .15 / agentic-web .10,
ренормализованные по присутствующим метрикам). Пороги в
`TIER_THRESHOLDS` в скрипте: mega ≥ 88, pro ≥ 76, flash ≥ 60, откалиброваны
по снимку 2026-10-11. Судятся только confidence high/medium (coverage
≥ 0.40); low — «не измерено», не вердикт. Переход предлагается только при
отступе > `MOVE_MARGIN` (1.0) от края полосы — шум за порогом не трогается.

Пороги — не истина, а калибровка. Менять — вместе с датой калибровки в
комментарии `TIER_THRESHOLDS`, чтобы следующая ревизия знала, откуда числа.

## Источники

- OpenRouter `/models` (benchmarks + цены) — с ключом из окружения, если задан.
- OpenCode Go `/zen/go/v1/models` — публичный; **требует браузерный User-Agent**
  (Cloudflare режет `Python-urllib` — уже вшито в `fetch_json`).
- arena.ai — **публичного API нет**; берём дневной архив
  [oolong-tea-2026/arena-ai-leaderboards](https://github.com/oolong-tea-2026/arena-ai-leaderboards)
  (GitHub raw, ходьба назад ≤10 дней — у краулера бывают провалы:
  2026-10-08..14 пусты, актуален 10-07). API-зеркало того же архива:
  `api.wulong.dev/arena-ai-leaderboards/v1`.
- Design Arena (designarena.ai) — уже приходит внутри OpenRouter
  `benchmarks.design_arena`; прямой API требует заявку на ключ
  (designarena.ai/developers/apply, 1–2 дня) — не заведено, пока не нужно.

Оба вспомогательных источника (Go, arena) деградируют, а не валят прогон:
их недоступность оставляет пометку в отчёте, а главный вопрос — размещение
по тирам — отвечается из OpenRouter + живого конфига.

## Сопоставление имён arena.ai ↔ OpenRouter

arena пишет `muse-spark-1.3-max`, `qwen3.8-max-0902`, `muse-spark-1.3 (xHigh)`;
OpenRouter — `meta/muse-spark-1.3`, `qwen/qwen3.8-max-0902`. Канонизация:
lowercase → срезать усилие (`-max/-xhigh/…`, `(Max)`) → срезать снапшот-дату
(`-0902`) → сравнить после слэша. При совпадении нескольких строк (снапшот и
семья) берётся максимальный Elo. Матчинг — единственное место, где ревизия
теряет точность; нематчед модели просто не имеют колонки арены.
