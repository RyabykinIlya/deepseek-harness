# OpenRouter model ranking for coding — findings

Generated by [`tools/openrouter-rank.py`](openrouter-rank.py); workbook in `../reports/openrouter-coding-rank.xlsx`.
Read this before trusting any single number below.

## How to read the score

Three metric sources are collected and kept in separate columns, because they
measure different things and disagree:

| Source | Field | Coverage | What it measures |
|---|---|---|---|
| Artificial Analysis | `coding_index`, `intelligence_index`, `agentic_index` | sparse (169/458 have a coding score) | absolute quality; the only real coding score |
| Design Arena | `elo` per category | broad (172/458) | pairwise preference; relative, not comparable across categories |
| Endpoints API | `uptime`, `latency`, `throughput`, `quantization` | all models, live | how a model behaves right now, not how good it is |

The composite `coding_score` is a weighted mean of min-max normalized metrics:
`coding_index` .40, `agentic_index` .20, `intelligence_index` .15,
`arena_codecategories` .15, agentic-web arena group .10. Weights are renormalized
over what a model actually reports, so `coverage` states how much of the total
weight that was. **A model with one metric can score 100 on it — read `confidence`
alongside `score`**, not the score alone.

`high` = coverage ≥ 0.75, `medium` = 0.40–0.75, `low` < 0.40.

## Is Gemma worth using?

**No, for this harness.** The numbers say coding and agentic ability diverge
sharply in Gemma 4:

| Model | coding_index | agentic_index | ratio |
|---|---|---|---|
| google/gemma-4-31b-it | 43.4 | 4.2 | 10:1 |
| google/gemma-4-26b-a4b-it | 39.3 | 2.9 | 14:1 |
| google/gemma-3-27b-it (older) | 10.1 | 0.1 | — |

Gemma 4 codes at a respectable mid-tier level (39–43, above Nemotron-Super and
Cohere-North) but its agentic index is the second-worst in the whole measured
field. `coding_index` measures writing code in one shot; `agentic_index`
measures holding a multi-step tool-using session together — which is exactly
what DeepSeek Harness does. A model that codes well but cannot sustain tool
loops fails the harness's core workload.

Gemma 3 is not competitive at all (2.7–10.1 coding). Gemma 4's jump to 39–43 is
real, but it lands in a band that free models already beat.

Separately, `google/gemma-4-*:free` sits in Google AI Studio's shared upstream
pool and returned persistent `429 upstream_provider_shared_pool` in every live
probe today. Unreliable on top of weak agentic ability.

(Thinking Machines, nvfp4 quantization).

## Live performance

Uptime and throughput come from the endpoints API and move constantly. Notes
from today's pass:

- `thinkingmachines/inkling*` — 99.4–99.9% uptime, single provider, nvfp4
- `nvidia/nemotron-3.5-lightning:free` — 88.3%, the least stable free model
- `google/gemma-4-*:free` — 100% reported uptime but persistent upstream 429,
  which uptime metrics do not capture (the request fails before the provider is
  marked down)
- Latency/throughput fields are `null` for most free endpoints: OpenRouter only
  reports them for endpoints currently serving traffic
